# 수담 오목 (omok-arena) 설계

작성일: 2026-11-20 · 원본 계획: `README.md`(사용자 제공)

## 1. 의도

PC와 휴대폰 브라우저에서 닉네임만으로 들어와 친구와 실시간으로 두는 15×15 오목 사이트.
가입 없는 HTTPS 주소로 공개하고, 외부 네트워크의 두 기기가 같은 방에서 대국할 수 있어야 한다.
PC를 꺼도 서비스가 돌아가야 한다.

## 2. 목표 / 비목표 / 실패 기준

목표 (사용자 계획 그대로)
- 로비: 닉네임 → 방 만들기(렌주룰/자유룰) 또는 방 목록에서 참가, 초대 링크로 바로 참가
- 서버가 좌석 2개, 차례, 착수, 승패를 관리하고 두 브라우저에 실시간 반영
- 새로고침한 플레이어는 기존 자리로 복귀
- 렌주룰 서버 판정: 흑은 정확히 5목 승, 흑 금수 3·3 / 4·4 / 장목은 이유 표시, 거짓 삼(열린 사가 될 수 없는 겉보기 삼) 처리, 금수와 5목이 겹치면 5목 우선. 백은 5목 이상 승. 자유룰은 양쪽 5목 이상 승
- 카카오 오목의 "방 목록 → 대국" 흐름, 나무색 판 + 독자 디자인, 내 돌 색·현재 차례·최근 착수 표시
- 모바일: 교차점 선택 → 확인 버튼으로 착수
- 테스트: 금수, 승패, 중복 착수, 두 클라이언트 동기화, 재접속
- README에 실행 명령과 공개 주소 기록

비목표 (이번에 안 함): 회원가입/로그인, 전적·랭킹, 채팅, 무르기, 시간제한, AI 대전, 카카오 상표·이미지 사용

실패 기준: 두 기기 화면이 서로 다름 / 금수 판정 오류 / 새로고침하면 자리를 잃음 / 모바일에서 오착수

## 3. 접근 방식

| 안 | 내용 | 결과 |
|---|---|---|
| **1. Vercel Functions + Upstash Redis** | 정적 화면 + 서버 함수(판정) + Redis(상태). SSE로 갱신 | **채택** (사용자 선택). PC 꺼도 동작, 추가 가입 없음, 지연 0.3~1초 |
| 2. Node 웹소켓 + Render | 가장 즉각적 | 미채택: Render 가입 필요, 무료 플랜 휴면(첫 접속 ~50초) |
| 3. 이 PC 서버 + Cloudflare 임시 주소 | 가장 빠른 구축 | 미채택: PC 상시 켜야 함, 주소가 바뀜 |

## 4. 구조

```
omok-arena/
├── public/          정적 화면 (빌드 없는 HTML/CSS/ES 모듈)
│   ├── index.html   로비 + 대국 (해시/쿼리로 화면 전환: /?room=ID)
│   ├── css/  js/
├── server/          순수 로직 (Vercel/Node 공용)
│   ├── renju.js     판정 엔진 (승리, 금수, 금수 이유)
│   ├── game.js      방·좌석·차례·착수·재대국 상태 전이 (순수 함수)
│   ├── store.js     저장소 인터페이스: Redis 구현 + 메모리 구현(로컬/테스트)
│   └── handlers.js  HTTP 핸들러 (요청 검증 → game → store)
├── api/             Vercel 함수 진입점 (handlers.js 를 얇게 감쌈)
├── tests/           node:test (단위·통합) + Playwright (두 브라우저, 모바일)
├── dev-server.js    로컬 실행: public/ 정적 + api 핸들러 + 메모리 저장소
└── README.md
```

- `api/`는 Vercel 규칙상 필요한 얇은 진입점이다. 로직은 모두 `server/`에 둔다.
- 로컬은 `node dev-server.js` 하나로 실행된다 (Redis 없이 메모리 저장소).

## 5. 상태와 동기화

- 플레이어 신원: 첫 방문 시 브라우저가 무작위 `playerId`(토큰)를 만들어 localStorage에 저장. 좌석은 이 토큰에 묶인다 → 새로고침해도 같은 자리.
- 방 상태(JSON, Redis 키 하나): `id, rule(renju|free), seats{black,white}(playerId, nickname), board[225], moves[], turn, status(waiting|playing|ended), result{winner, reason, line}, version, updatedAt`.
- 착수/입장/재대국은 `POST` → 서버가 검증 후 `version`을 1 올려 저장. 동시 요청은 Redis Lua 스크립트로 "읽은 version 그대로일 때만 저장"(compare-and-set) → 중복 착수 방지.
- 갱신 전달: `GET /api/rooms/:id/stream` SSE. 함수가 Redis의 `version`을 짧은 간격(약 400ms)으로 확인해 바뀌면 상태를 보내고, 약 25초 뒤 닫는다. 브라우저 `EventSource`가 자동 재연결한다. 로비 방 목록도 같은 방식.
- 방 정리: 마지막 활동 후 2시간 지나면 Redis TTL로 삭제. 방 목록은 Redis 정렬 집합(updatedAt).

## 6. 대국 흐름

1. 로비: 닉네임 입력(localStorage 기억) → 방 목록(규칙, 인원, 상태) / 방 만들기(방 이름, 렌주·자유)
2. 방 만든 사람이 흑, 들어온 사람이 백. 두 자리가 차면 바로 시작
3. 초대 링크 `https://<주소>/?room=<ID>` 복사 버튼. 링크로 오면 닉네임 입력 후 빈자리에 앉음
4. 자리가 다 찬 방에 들어오면 관전(읽기 전용)
5. 대국 종료 → 승리 줄 강조, 사유 표시 → "다시 두기"(양쪽 동의 시 흑백 교대해 새 판), "기권", "나가기"
6. 상대가 나가도 자리는 유지(재접속 가능). 상대 연결 상태는 표시하지 않음 (내 판단: SSE 단발 연결로는 신뢰도 낮음)

## 7. 렌주 판정 (server/renju.js)

- 5목 판정: 착수점 기준 4방향 연속 개수. 흑은 정확히 5 = 승, 6 이상 = 장목(금수). 백·자유룰은 5 이상 승
- 우선순위: 흑 착수가 정확히 5를 만들면 3·3/4·4가 동시에 생겨도 승리
- 4·4: 착수 후 "다음 한 수로 정확히 5가 되는 점"이 있는 방향(사)이 2개 이상 (같은 줄 안의 두 사 포함)
- 3·3: 착수 후 "열린 삼"이 2개 이상. 열린 삼 = 한 수를 더 두면 열린 사(양쪽 모두 5가 가능한 사)가 되는 삼. 그 한 수가 흑에게 금수(3·3, 4·4, 장목)라면 열린 사가 될 수 없으므로 거짓 삼 → 재귀 판정
- 반환: `{ ok, win?, line?, forbidden?: '33'|'44'|'overline', reason: '흑 3·3 금수' ... }`
- 흑 차례에는 서버가 금수점 목록을 상태에 넣어 보내고, 화면에 × 표시한다
- 테스트: 기본 승패 / 장목 / 3·3 / 4·4 / 한 줄 4·4 / 거짓 삼(사가 장목·금수로 막힘) / 5목+금수 동시 / 가장자리 / 백 장목 승 / 자유룰 6목 승

## 8. 화면

- 나무색 판, 독자 디자인(카카오 상표·이미지 미사용). 세부 비주얼은 frontend-design 스킬로 결정
- 대국 화면: 판, 양쪽 플레이어 카드(돌 색, 닉네임, "내 차례/상대 차례"), 최근 착수 표시, 규칙 배지, 수순 번호 토글은 하지 않음(비목표)
- 모바일(터치): 교차점 탭 → 반투명 미리보기 + 확대 표시 → 하단 "착수" 버튼. 데스크톱(마우스): 클릭 즉시 착수, 호버 미리보기
- 판은 SVG로 그려 화면 크기에 맞춰 늘어난다

## 9. 테스트와 검증

- `node --test`: renju 단위, game 상태 전이, handlers + 메모리 저장소 통합(두 클라이언트 착수 동기화, 중복 착수, 재접속)
- Playwright: 데스크톱 + 모바일 에뮬레이션 두 컨텍스트로 방 생성 → 링크 입장 → 착수 동기화 → 금수 → 승패 → 새로고침 복귀
- 배포 후 같은 시나리오를 공개 주소로 반복 (외부 네트워크 접근은 공개 HTTPS 주소로 확인)

## 10.5 검토 후 결정 (Claude 판단, 사용자 확인 대상)

- **금수에 두면**: 착수를 거절하고 이유를 보여준다(패배 처리 아님). 화면의 × 점은 누를 수 없다. 서버도 거절한다.
- **무료 한도 유지**: Upstash 무료 명령 한도를 지키려고, 대국 중 SSE는 작은 `version` 키 하나만 약 1초 간격으로 확인하고, 탭이 숨겨지면(Page Visibility) 연결을 끊었다가 돌아오면 다시 연결한다. 로비 방 목록은 SSE 대신 5초 폴링 + 새로고침 버튼.
- **나가기**: 대기 중·대국 종료 후 "나가기"는 자리를 비운다. 대국 중 "나가기"는 "기권하고 나갈까요?" 확인 후 기권 처리. 새로고침·탭 닫기는 자리를 유지한다(복귀 가능).
- **렌주 첫 수 (사용자 결정)**: 렌주룰 방에서 흑의 첫 수는 판 정중앙(7,7)만 허용한다. 자유룰은 제한 없음.
- **원본 계획**: 사용자가 붙여 넣은 계획을 그대로 `README.md` 상단에 둔다(문서 범위와 동일).
